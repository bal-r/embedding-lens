What does a video embedding see?

Six videos, cut into five-second moments. Each moment becomes a single vector in a space it shares with language, and we ask which words land closest.

How it works

  1. 1

    Cut

    289 published moments of 5 seconds, sampled at two frames per second.

  2. 2

    Embed

    A model turns each moment into one vector, in the same space it maps sentences to.

  3. 3

    Read out

    Rank up to 119,000 words and phrases by closeness, and check the result against the frames.

    Rerank

    Fetch fifty, then look again

    Cosine similarity compares two vectors that were made apart. A reranker reads the video and one phrase together and answers “does this describe it?”. Too slow for a whole vocabulary, so it only re-sorts the embedding's top 50.

    Follows the moment, model and words picked in Explore. Reranker: Qwen3-VL-Reranker 2B.

    Lab

    What the experiments showed

    Small, reproducible experiments behind this page. A readout can find its original video while describing it poorly: retrieval usefulness and visible correctness are different things.

    The study covers 291 moments from six videos and three embedding models. Phrase correctness was evaluated on 12 moments by one AI annotator. These are exploratory findings, not a general model benchmark.

    Inspect the experiment code, recorded metric agreement and phrase judgements.

    Live features

    Everything on this page works from precomputed results. Free-text search and scoring words outside the built-in vocabulary need the embedding models, served from embedding-lens-api.balta-tech.com. When that is offline, run the backend yourself:

    git clone https://github.com/bal-r/embedding-lens
cd embedding-lens && uv sync
uv run uvicorn lens.api:app --port 8000

    Then point this page at it from the browser console: localStorage.setItem("embedding-lens:api", "http://localhost:8000") and reload.
